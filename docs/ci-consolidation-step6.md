# CI consolidation — 6/10 shared build

The central required workflow already builds a standard artifact once and shares it with the full breed, dialog, search and directory consumers. This step extends reuse to LOST-FOUND-1 when required validation produces a build, verifying exact merge revision and dist fingerprint; only scope paths with no central artifact retain the existing standalone build. A failed or missing expected artifact is not silently rebuilt.

The exact-head DS-0B and SEO public regression jobs previously each ran the same local profile build via start-public-regression-ci.sh. DS-0B now also serves as the shared local producer when SEO is selected, even for SEO-only changes. It records the local profile, exact PR head, Node version, lockfile, registry and dist fingerprint. SEO downloads only from the same workflow run and verifies before starting independent local D1. No cross-workflow downloads, no production access. On push DS-0B keeps its prior Node-only behavior. The central aggregate requires the shared producer on SEO-only PRs. Existing gate names retained. Standard and local artifacts must stay separate because vite.config.ts changes auth bindings for local E2E; the explicit source revision override is restricted to local E2E. Review standard/local profiles and remaining standalone feature workflows still build independently and will need further consolidation. No guarantee of exactly one build for all PRs yet.

Expected reduction for simultaneous central, LOST-FOUND, DS-0B and SEO checks: four builds to two compatible profiles, assuming the central scope produces its artifact. Runtime not measured. Contract tests added; full CI pending.
